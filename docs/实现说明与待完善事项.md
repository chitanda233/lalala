# 实现说明与待完善事项

更新日期：2026-10-18。当前规则版本 15，存档版本 5。本文件区分用户明确要求、实现选值与仍需完善的边界。最新简化产出规则覆盖旧版复杂算法。

## 已确认的产出规则

| 用户要求 | 当前落实方式 |
| --- | --- |
| 主食影响较重，饮料负责物态和颜色 | 自由组合硬度按食物 70%＋饮料 30% 合并；凝聚、延展、颗粒、蓬松以食品原有属性为主 |
| 每款普通便便有固定配方 | 46 款普通款（含 uncommon）各一条食物集合＋饮料＋力度区间的配方；不要求添加剂 |
| 普通配方有 80% 定向产出 | 先抽稀有，未中时目标款占普通分支 80%；基础稀有 2% 下，总体目标为 78.4% |
| 益生菌让配方稳定 | 配方匹配且选择益生菌时，目标款占普通分支 100%，总体为 98%；稀有分支仍保留 |
| 添加剂保持单选，可以不加 | 最多 1 种；益生菌、装饰剂、稀有功能剂不能同时叠加 |
| 稀有每轮都有机会 | 10 款稀有默认合计 2%，每款基础 0.2%，不设食物、饮料、水量、力度、马桶或标签资格门槛 |
| 功能添加剂增加对应稀有机会 | 单个功能剂对其稀有目标合计增加 3 个百分点，多目标均分；稀有合计变为 5% |
| 闪粉等应看得见 | 闪粉、金箔、花瓣等直接叠在实际产出上，保留本款形态和固定分类 |
| 算法容易控制和检查 | 概率预告与实际抽取共用规则，固定配方与五项形态属性集中定义 |

80% 是未抽中稀有后的条件概率。选择稀有功能剂时，匹配配方目标的总体概率为 `95% × 80% = 76%`，其他普通合计 19%，稀有合计 5%。不加添加剂也可以命中固定配方。

完整规则见 [便便产出算法说明](便便产出算法说明.md)，46 条实际配方见 [固定配方表](固定配方表.md)。

## 为实现规则作出的数值选择

以下是清楚列出的实现选值，后续可以直接调，不隐藏在多层权重中：

| 项目 | 实现选择 |
| --- | --- |
| 形态属性 | 硬度、凝聚、延展、颗粒、蓬松，均为 1～7；硬度 1 软、7 硬 |
| 多食物合并 | 沿用食品原有影响强度，主食谷物权重乘 2，分别加权平均；保留现有食品调参 |
| 饮用量 | 仅对自由组合硬度作最多 ±1 修正；不影响固定配方匹配 |
| 普通自由分配 | 以五项属性差异、食物集合和饮料接近程度排序，只取最近 3 款，按 1 /（1 + 距离）分配；固定目标除外 |
| 力度区间 | 轻 0～33，中 34～66，强 67～100 |
| 力度指针 | 开始后摆动，3 秒往复；停止时锁定 |
| 揭晓 | 锁定后约 400 ms |
| 消化时间 | 2 / 4 / 8 / 随机过程设置，不影响产出概率 |
| 马桶 | 保留外观、解锁和评分反馈，不影响产出概率 |
| 品种 | 56 款：46 普通、10 稀有；每款只有一个固定 Bristol 分类 |

稀有功能剂的“＋3 个百分点”是当前明确的实现选值，不能读作倍率 ×3。选它就占用唯一的添加剂槽，不再同时叠加益生菌。

## 删除的旧规则

- 各结构组稀有合计 0.5% 封顶，以及“先有来源资格才有机会”。
- 普通条目按 35% 触发稀有材质涂层；稀有现在产出其自己的固定品种。
- 食物、饮料、设备、标签和时间反复相乘的候选倍率。
- 消化档位的 +1 / 0 / −1 形态偏移、设备的稀有倍率，以及水量的 −3 / −2 / −1 多段隐藏偏移。
- 先抽形态、再分组缩放稀有权重、最后再改材质的多层不透明流程。

仍保留个体外观种子、食材印记、颜色和得分，它们各自负责展示或反馈，不再变成另一层稀有概率。

## 外观、独立个体与图鉴

每款便便有明确的五项形态属性、固定结构、固定分类和实际素材。稀有款拥有自己的固定形态；普通款上的金箔、闪粉等是装饰，不会伪装成另一个稀有图鉴条目。

每次产出保存独立 ID、实际品种、颜色、食材印记、装饰和变化种子。同款新个体不覆盖旧个体，颜色与残留不新增品种。金针菇沿用自身印记，其他食物按保留度体现。

图鉴默认对未发现款显示统一虚影；右上角“全部样式”可临时查看 56 款完整造型与大图，不写收藏记录。软块要保持独立块体，糊状呈现塌落、抹开、碎边相连；水样款保留水滩、拖尾、涟漪和压力喷溅的不同轮廓。

当前采用开发期渲染的透明 PNG，运行时用 SVG 包装和外观叠层。可旋转的实时 3D 展示与参考资料中的五档品质仍未实现。

## 单局与后台

开始时保存本局身份和选择、启动力度指针；停止时按锁定力度生成结果；约 400 ms 后结算。结果冻结后刷新不重新抽取，同局不重复发放。

Admin 是独立开发工具，食品的九项属性与色素仍可编辑，保持用户已有数值。便便五项属性、固定配方、饮料、添加剂和马桶内容在源码定义。Admin 的配方预览必须使用相同产出规则，不能继续展示旧的 0.5% 或 35% 文案。

正式构建继续排除 Admin、管理接口和开发脚本。玩家存档依旧保存在本地。

## 需要明确的边界与后续决定

| 项目 | 当前事实与边界 |
| --- | --- |
| 固定配方内容 | 每款一条且输入唯一；组合本身是策划初版，可直接替换而无需改概率算法 |
| 自由组合平衡 | 用五项属性匹配普通款；还需要根据试玩结果调食物、饮料及便便属性 |
| 金针菇 | 用户要求必定体现，现有保留度可编辑；将其调成 1 的边界仍需保持明确 |
| 收藏节奏 | 56 款和固定配方已明确，正式解锁曲线、重复游玩目标、保底机制未定 |
| 外观变化 | 同款共享基础轮廓，个体差异主要来自颜色、纹理、残留、装饰和小幅姿态 |
| 管理范围 | Admin 主要管理食物参数，其他内容尚没有完整的可视化增删改页面 |
| 时间单位 | 2 / 4 / 8 是游戏过程档位，未承诺现实小时或医学反应 |
| 存档 | 本地存储与独立个体保留；正式容量控制、备份及云同步策略未定 |
| 验证范围 | 本轮按规则和受影响界面作最小必要验证；历史通过数不等于新规则验收，不声称完成 iPhone Safari 真机验收 |

内容清单可使用 `node scripts/generate-content-docs.mjs` 重新生成，并用 `--check` 检查同步；它不会修改食物调参数值或玩家存档。固定配方表和算法说明也应与源码一起维护。
