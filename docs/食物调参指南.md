# 食物属性与本地调参后台

更新日期：2026-10-18。规则版本23。食物属性参与物态、真实颜色与连续配方相似度。理想配方通常为普通分支80%，独候选为100%；益生菌对任何合法组合都稳定普通主结果100%。调参改变物态时需重查配方表。它们是游戏参数，不能当作现实中的营养或健康结论。

后台已整合为完整内容管理工具，先在顶部选择「食物管理」进入原有调参台。其他模块与统一保存规则见 [后台管理指南](后台管理指南.md)。

## 打开与保存

在项目目录运行 `npm run dev`，然后打开 `http://127.0.0.1:4173/admin/`。如果本地游戏使用其他端口，在同一个地址后加上 `/admin/`；例如当前预览为 `http://127.0.0.1:4174/admin/`。

需要指定端口时使用 `LALALA_PORT=4174 npm run dev`；发布预览也使用同一环境变量，例如 `LALALA_PORT=4176 npm run preview`。

后台读取全部食物的当前配置。选择食物并调整参数后保存，修改会写入项目中的 `src/content/food-attribute-values.js`，可以用 Git 查看差异、提交或恢复。它不会写进玩家的浏览器存档。保存后刷新游戏页，尚未抽取结果的单局会使用当前配置；已经停止指针并锁定的结果按原快照恢复。只点击开始时还没有结果，也没有保存完整参数副本。

常用操作：

1. 在「食物库」按分类筛选，选中要调整的食物。
2. 在食物介绍下方调整独立的「整份食物的影响强度」，再调整六项主要属性与「食物颜色」；展开「高级参数」可调整蓬松度和顺滑度两项。
3. 在「边调边看」比较「已保存」和「当前草稿」的七型概率、代表外观、固定目标实际概率与稀有合计；可加入两种搭配食物，调整饮料及饮用量、阶段与力度，并单选添加剂或不加。随机阶段展示三档混合分布；马桶不改变产出概率。
4. 点击「保存到项目 · N」一次保存所有修改过的食物，而不只保存当前选中的食物。

「还原这份食物」只撤销当前食物未保存的修改。「重新读取磁盘」重新加载所有配置，有未保存修改时会要求确认；切换食物本身不会丢失草稿。

同时打开多个后台时，保存会校验配置版本。如果别人或另一个页面已经保存，旧页面的提交会被拒绝，避免覆盖较新的修改。重新载入当前配置，再应用自己的调整。

## 整份食物的影响强度

「影响强度」`influence` 是整份食物在混吃配方中的相对权重，位于食物介绍之后、六项主要属性之前，始终显示，不需要展开高级参数。它会影响整体形态、颗粒、蓬松、顺滑和主要色素来源的选择，是独立于染色能力的整体设置。

数值为 1–7：1 更像轻微点缀，7 更容易主导混搭。单吃一种食物时没有其他食物需要竞争，提高这项数值不会把所有效果机械放大；可加入两种搭配食物比较实际变化。保存、还原和切换食物时，它与其余参数一起保留。

主食谷物合并形态时会额外乘 2 倍权重，使主食影响更重。主要色素仍按原始影响强度与染色能力选择。固定配方目标的 80% / 100% 不因编辑这些数值而改变。

## 六项核心属性

所有数值均为 **1–7 的整数**。软硬程度固定为 **1 非常软、7 非常硬，4 居中**；其他属性数字越大，代表该项效果越明显。数值不是百分比，也不是指定的布里斯托类型。

| 属性                     | 低值的表现                         | 高值的表现                         |
| ------------------------ | ---------------------------------- | ---------------------------------- |
| 软硬程度 `softness`      | 1 非常软，提高糊状与水样形态的机会 | 7 非常硬，提高干硬颗粒等形态的机会 |
| 凝聚度 `cohesion`        | 容易分散、断成多个部分             | 更容易连成整体，连续造型更有机会   |
| 延展性 `elongation`      | 紧凑、短小                         | 长条、弯曲与盘卷造型更有机会       |
| 颗粒感 `grain`           | 表面细腻                           | 表面有更多颗粒纹理                 |
| 形态保留度 `retention`   | 食材印记弱或不出现                 | 更明显地保留食材自己的形态与纹样   |
| 染色能力 `colorStrength` | 较多保留原本底色                   | 更明显地染成指定色素颜色           |

布里斯托图鉴仍保持 **1 型为硬颗粒、7 型为水样**，与软硬程度参数的数字方向相反。现在按食品软硬旋钮、食材偏置、影响强度、饮用量与阶段和添加剂计算湿软指数 S；主食额外乘2。所选饮料的饮用量由原拉条控制，0–1250 mL，5段、每段250，默认750；0 mL不计饮料效果；阶段2偏湿、8偏干。现有食品参数保持用户已有数值。

**凝聚和延展控制不同的事。** 凝聚影响连接与分散，延展影响长度和弯曲；高凝聚、低延展可以是完整的紧实团，高凝聚、高延展则偏向连续长条。它们会影响形态和造型候选，但不会绕过布里斯托七型的外观边界，例如水样便不会因为延展性高就变成完整面条。

形态保留度控制实际食材印记，不需要再增加一个重复的“难消化”参数。染色还需要选择 `pigmentId`；没有指定色素时，仅提高染色能力不会凭空产生一种颜色。稀有材质保持自己的配色。

## 两项高级属性

| 属性               | 调整的结果                                                           |
| ------------------ | -------------------------------------------------------------------- |
| 蓬松度 `porosity` | 影响表面孔洞、气泡纹理，并使自由组合更接近蓬松款 |
| 顺滑度 `lubricity` | 影响顺畅评分，不再作为形态或稀有概率倍率；不直接等同于软化 |

界面分为一项整体影响强度、六项核心属性和两项高级属性，共九项数值，范围均为 1–7。保持其他条件相同，依次改变一个属性，比较形态概率和实际出场表现，比连续改动多项更容易找到合适数值。

## 三个设计例子

- **年糕**：提高凝聚度与延展性，得到连贯、能拉长的造型倾向；软硬程度决定它最终更偏紧实还是柔软。
- **玉米**：提高颗粒感与形态保留度，保留玉米的辨识度；不必同时把凝聚度设高。
- **墨鱼汁意面**：提高延展性，选择深色素并提高染色能力；面条感和深色是两个独立维度。

一顿最多三种食物，选择顺序不会改变配方结果。先核验物态与来源，再按食物、饮料、饮用量和阶段的连续相似度分配身份；力度只调整同身份内造型。理想配方不是精确开关。装饰四款需要指定材料。金针菇印记可叠加不同形态和底色，默认保留度下确定显示。

## 读取固定配方与稀有预览

后台使用与实际游戏相同的最终候选池，代表外观取概率最高的普通款，属于稳定的比较示例，不是一次历史结果。

| 预览组合 | 固定目标的总体概率 | 稀有合计 |
| --- | ---: | ---: |
| 配方匹配，不加添加剂 | 78.4% | 2% |
| 配方匹配，益生菌 | 98% | 2% |
| 配方匹配，稀有功能剂 | 76% | 5% |

每轮先判定稀有；未中后，多候选理想目标默认占普通分支80%，独候选为100%。益生菌对所有合法组合稳定当前主结果100%。添加剂最多单选一个，可以不加；不加益生菌也能匹配固定配方。其他功能剂可能改变实际物态或主色，需要重新核验来源；装饰直接叠在实际样式上。

调参可能改变实际物态与主色，使原目标失去资格；不能强行保留旧结果。若仍满足来源和物态且位于理想锚点，通常80%的普通分支口径保留；自由组合按相似度连续变化。后台显示当前合法主结果及实际概率。完整组合见 [固定配方表](固定配方表.md)。

## 稀有款与发布

10 款稀有每轮都有机会，基础各 0.2%，合计 2%，没有食物、饮料、力度、水量或来源标签门槛。单个稀有功能剂对其目标合计增加 3 个百分点，稀有合计变为 5%；多个目标时均分加成。稀有使用自身固定造型，不给普通款另抽 35% 材质涂层。精确映射见 [算法说明](便便产出算法说明.md)。

发布前运行 `npm run build`。发布产物位于 `dist/`，只包含游戏运行需要的文件，排除本地管理页面、管理接口、源码写入能力和开发工具。`npm run preview` 用于预览这份发布产物；后台仅随本地开发服务提供。保存过的食物属性会作为游戏内容进入发布产物。
