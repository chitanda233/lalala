## 文档怎样区分来源

“用户需求”表示对话明确提出或接受的方向；“实现补充”表示我选择的名单、阈值、公式、展示细节或技术方案；“待定/差距”表示尚未成为正式内容规则，或当前实现存在边界。

内容表记录**当前源码配置**，包括已通过 Admin 保存的调参，不推断每个数值是谁修改的，也不把现有实现自动视为用户逐项认可的正式策划。

统一美术参考中的五档品质、可旋转查看等属于资料建议。已经明确采用的统一视觉要求写入需求文档；未实现的建议不写成完成事项。

## 更新内容清单

食物、饮料、添加剂、便便和马桶五份文档由脚本读取真实内容生成，避免手工表格停留在过时初值：

```sh
node scripts/generate-content-docs.mjs
node scripts/generate-content-docs.mjs --check
```

生成器只写这五份 Markdown，不改游戏、玩家存档或食物参数。调整内容后重新生成；用户需求与自主实现的归属说明由人维护。算法报告中的数字示例是指定配方的核对快照，不会随后台调参自动更新。

最近一轮游戏验证记录为 71 项单元测试、64 项浏览器测试通过；它说明当前实现通过这些检查，不代表全部正式发布方案已经敲定，也不代表已在 iPhone 真机上完成验收。
