# 后台管理指南

更新日期：2026-10-23。规则版本24。

运行 `npm run dev`，打开 [本地管理后台](http://127.0.0.1:4173/admin/)。如使用自定义端口，在游戏地址后加 `/admin/`。默认显示总览，顶部切换模块，地址中的 `#stools`、`#recipes` 等可直接定位模块。

## 管理内容

| 模块 | 当前数量 | 可调整内容 |
| --- | ---: | --- |
| 食物管理 | 53 | 九项属性、色素、食物混搭与实时产出预览 |
| 大便管理 | 56 | 名称、分类名称、描述、材质、主色、高光色、五项物态属性、生成身份、造型偏好力度与来源 |
| 大便配方 | 46 | 推荐的1–3种不同食物、饮料、0–1250 mL饮用量、力度与可选添加剂 |
| 图片展示 | 56 | 七型和稀有度筛选、分页、大图、透明棋盘 / 浅色 / 深色背景、主图素材选择 |
| 饮料管理 | 11 | 名称、分类、描述、效果说明、软硬、蓬松修正、顺畅评分、颜色、图标、标签 |
| 添加剂管理 | 18 | 名称、说明、功能开关、颜色、符号、装饰、材质特效、属性修正、顺畅评分、任意稀有目标组、标签 |
| 马桶管理 | 10 | 名称、描述、材质、特点、造型、配色、顺畅评分、初始解锁或累计次数解锁、标签 |

条目按分类、分页浏览。大便资料右侧可以打开关联配方、查看大图；配方可以一键放入食物管理的「配方试验」；饮料可以查看关联配方。固定 ID、布里斯托分类、稀有度和造型标识保持不变，维持现有 56 款图鉴与存档引用。

名称与说明作为纯文字保存，不支持 HTML。软硬数值越大越硬，五项物态属性使用 1–7 整数量表。标签使用已有游戏效果的英文标识，以英文逗号分隔；新增一个标签名称本身不会新增游戏逻辑。饮料和添加剂当前均直接可用，不提供尚未接入游戏的解锁设置。

## 草稿与保存

切换条目、分类或模块都会保留草稿。条目与导航上的圆点表示存在未保存修改，顶部「保存到项目 · N」保存所有模块的调整。「还原此条目」仅撤销当前条目的草稿；「重新读取磁盘」会重新加载全部配置，有草稿时先确认。

- 食物属性写入 `src/content/food-attribute-values.js`，保留原有自定义调参。
- 其他模块写入 `src/content/managed-content.js`；游戏内容模块直接读取这份数据。
- 保存使用版本校验和临时文件原子替换。旧窗口的配置被修改后，再保存会报告冲突并保留草稿。
- 两份配置文件分别写入；若一份保存成功、另一份失败，已保存部分保留，失败部分仍是草稿，顶部会显示错误和剩余条目数。
- 保存后刷新游戏页使用新配置。现有便便个体的快照和收藏记录不被后台改写。

## 配方与效果

后台是用户手动配置工具。按用户最新要求，任何游戏配置都应允许保存，来源、配方与物态等默认玩法约束不能成为保存限制；不一致之处可以提示，实际效果与概率应准确展示。明天见丝丝、明天见喷射默认要求金针菇，用户可以手动修改或移除来源条件，游戏按保存后的条件执行。

推荐搭配使用食物集合、饮料种类与饮用量、推荐力度、可选添加剂，食物顺序不影响；46款普通推荐与10款主题搭配已按新水量公式校准。消化时间及其影响已移除；后台保留力度预览、推荐力度区间与造型偏好编辑。力度在同型同身份内调整造型概率，不改变身份总预算。四款装饰品种仍需对应添加剂来源。推荐不是精确开关，也不提供固定80%命中奖励；手动编辑后的指定目标概率按实际配置重新计算。

配方重复、来源不符、物态不符和缺少无门槛基础候选只进入顶部可展开的“配置提示”，不会阻止保存；食品色素单独修改也可正常保存。未知引用、无效数值和不安全图片路径仍会被拒绝。若手工配置使某个餐盘没有任何合法普通候选，后台明确显示预览不可用；游戏取消该次生成并提示检查配置，不发放非法结果或增加次数。

大便物态属性参与自由组合候选匹配，不改变该条目的固定图鉴分类。马桶仅影响场景和顺畅评分，不影响产出概率。添加剂关联组共享20%，平均分配；存在关联组时，组外稀有0、普通80%。可配置任意有效目标数量、材质特效和表面装饰；只有启用物态／结构功能时，属性修正才参与物态或普通选型。益生菌稳定配方的功能仍由固定 ID `probiotic` 决定。

效果说明文字独立编辑，调整数值后同步修改说明，以保持玩家看到的文字准确。

## 图片素材

点击图片卡片打开大图，可选择项目 `assets/stools/` 内已有的 PNG / WebP 作为主图。新增图片文件放入该目录后，点击「重新读取磁盘」更新素材列表。保存接口会拒绝目录外路径和不存在的文件。

「使用默认分层造型」恢复该款的主体、装饰与食材印记渲染。选择主图时沿用游戏的主图渲染规则，普通主图按实际主色染色，玉米与金针菇参考图保留黄色颗粒和浅色细丝；稀有图片保留自身材质色。图片选择是草稿，仍需点击顶部「保存到项目」。更换图片不增加图鉴条目。

## 发布

`npm run build` 将保存后的配置和素材放入 `dist/`。管理页面、接口和写文件能力不进入发布包；`npm run preview` 不提供后台。

## 生成来源与主结果（规则24）

大便管理包含生成身份、造型偏好力度、必需食物、来源标签、实际主色素和必需添加剂，与配方页的推荐餐盘分开。默认配置每型至少保留一个无来源门槛的基础候选；这些是默认内容设计，不能限制用户手动保存。

普通候选先满足真实来源与实际物态，再按推荐食物品类（60%）／标签（40%）相似度与五项结构偏差评分。带来源要求的普通主题候选与通用候选并存时，普通预算按70%／30%分配；每层25%均匀保底、75%按权重分配。力度在同型同身份内调整造型权重，不改变身份总预算。后台分别展示实际主结果与指定目标的概率，益生菌稳定当前普通主结果，不保证被手动配置为不可达的指定目标。

无关联组时，全体稀有均分基础2%，普通合计98%；有效关联组共享20%，组内均分、组外0%，普通合计80%。普通与稀有合成统一池，只抽取一次。

## 发布前验证

`npm run verify` 依次检查 JavaScript 语法、六份生成文档、单元测试和浏览器交互。首次运行浏览器测试前执行 `npx playwright install chromium`；也可通过 `LALALA_CHROME` 指定已有 Chrome。GitHub Pages 工作流安装依赖和测试浏览器，全部检查通过后才构建、上传和部署游戏。

后台与图鉴的指定目标概率按品种 ID 读取实际候选池，和“当前主结果”分别显示。手工配方使指定目标不可达时显示 0%；益生菌只稳定实际普通主结果，不能把不可达目标变成 98%。稀有主题页也核对当前关联组，本款被移出时显示 0%。
