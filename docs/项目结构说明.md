# 项目结构说明

更新日期：2026-10-19。规则版本23，存档版本7。项目使用原生 ES Modules，规则和内容不依赖 DOM；src/main.js 连接存档与界面。

## 内容与规则入口

| 文件 | 职责 |
| --- | --- |
| content/foods.js、expanded-foods.js | 53种食品及分类、解锁、描述；熟甜菜根和蒸土豆独立默认参数 |
| content/food-attribute-values.js | 用户已保存的食品九项调参，本次没有覆盖 |
| content/food-wetness.js | 从现有软硬值映射湿软值的食材质地偏置 |
| content/managed-content.js | 现有后台统一维护的便便、配方、饮料、添加剂、马桶及素材配置 |
| content/stool-recipes.js | 46条普通完整配方，按ID索引 |
| content/rare-theme-recipes.js | 10款稀有主题搭配，仅展示，不设掉落门槛 |
| content/recipe-labels.js | 饮用量与阶段的共享文本 |
| game/selection.js | 有效ID、饮用量取值、阶段、食物去重和添加剂单选 |
| game/source-conditions.js | 实际食物、标签、主色与添加剂来源过滤及中文来源说明 |
| game/color.js | 从真实餐盘计算主色，抽中图鉴不制造颜色 |
| game/physical-state.js | 湿软指数S及基础普通类型；不读取力度 |

| game/drops.js | 从同一最终池抽取个体，锁定颜色、残留与外观种子 |

## 选择对象

```js
{
  foodIds: ["rice"],
  drinkId: "water",
  water: 1250,         // 所选饮料的饮用量：0–1250 mL，每档250
  digestionTime: "4",  // 游戏阶段2 / 4 / 8 / random
  additives: [],        // 最多一种，可不加
  force: 50,
  toiletId: "standard"
}
```

所选饮料的水分摄入仅由原拉条决定，`water` 为饮用量。随机阶段的后台预览按三个确定阶段的最终分布等权合并；真正开始时抽定一个阶段，存进本局与个体。力度不改变S，马桶不改变产出概率。

## 普通配方

```js
{
  characterId: "classic",
  foodIds: ["rice"],
  drinkId: "water",
  water: 1250,
  digestionTime: "4",
  forceZone: "medium",
  requiredAdditive: null
}
```

理想配方是连续插值的锚点；完整匹配通常给普通分支80%，独候选为100%。任何合法组合都有主结果，益生菌稳定至100%。来源条件保存在普通图鉴generation中，先于相似度检查；力度只进入同身份内造型分配。

无关联组时，全体稀有均分基础2%；有有效关联组时，仅组内均分20%，组外0%，普通80%，不叠加基础预算。稀有主题不是固定配方，也不改变资格或预算。精确公式及实际分数见 [算法说明](便便产出算法说明.md) 和 [固定配方表](固定配方表.md)。

## 界面、素材与后台

图鉴仍为56款、每款固定一种Bristol类型；颜色和残留不新增ID。未知条目统一虚影，右上角“全部样式”仅调试显示。详情可切换形态、完整配方和来源条件，稀有页提供主题搭配并说明无来源门槛。

美术入口为 ui/artwork/stools.js。19款高清参考PNG映射至 assets/stools/reference-v2/，其余37款使用原生预渲染PNG；真实透明边缘裁切食材和功能装饰。原六格低清图集退出运行时引用。明天见喷射保留原第7型，不改螺旋。

游戏只用 styles.css，按手机单屏布局。饮料面板用原拉条显示所选饮料的唯一饮用量；消化面板说明游戏阶段；主界面不提前展示预测品种、概率或随机抽定阶段；后台按三个消化阶段的实际候选池预览。列表使用分类与分页，不新增搜索。

admin/ 保留现有内容工作台，新增配方饮用量与阶段、材料门槛和饮料湿软偏置编辑。试验、后台与游戏共用最终池。scripts/admin-api.mjs 校验数据结构、引用与数值范围，串行写入并检测磁盘版本冲突；配方重复、来源和物态不符只在后台提示，不阻止保存；新增食品缺省值只在读取时补齐，原九项参数不被覆盖。正式构建排除Admin与管理API。

本地存储键 lalala-dev；单局ID和Web Locks防止重复结算。规则版本升级会使旧版未完成单局失效，已记录个体仍保留。验证按本轮影响范围进行，未声称Safari真机验收。

## 文档生成

node scripts/generate-content-docs.mjs 从源码生成食物、饮料、添加剂、便便、马桶与固定配方表六份中文文档，包括真实S与概率；--check检查同步。原始设计归档于 [新配方设计原稿](新配方设计原稿.md)，后续用户答复及当前实现优先。

普通图鉴的 `generation` 包含身份分组identity、通用标记base、来源sources（foods/tags/pigment/additives）与造型偏好forceZone。后台持久化这些字段并校验数据结构与引用；默认内容每型保留一个无门槛base，手工配置不满足时只提示。来源与物态是硬条件，配方只影响连续相似度。
