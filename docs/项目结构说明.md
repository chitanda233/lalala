# 项目结构说明

更新日期：2026-10-18。规则版本 15。项目使用原生 ES Modules，内容与规则不依赖 DOM、音频或 localStorage；`src/main.js` 连接规则、存档与界面。

## 模块边界

下表的路径均相对 `src/`：

| 文件或目录 | 当前职责 |
| --- | --- |
| `config/game.js` | 数量限制、规则版本、普通 80% / 益生菌 100%、稀有 2% 与功能剂＋3 个百分点 |
| `content/foods.js`、`expanded-foods.js` | 51 种食物、分类、解锁和描述 |
| `content/food-attribute-values.js`、`food-attributes.js` | 用户食物调参、九项属性校验与显示 |
| `content/drinks.js` | 11 种饮料、硬度、蓬松修正、颜色与评分效果 |
| `content/additives.js` | 18 种单选功能剂，稳定度、属性修正、装饰与对应稀有目标 |
| `content/toilets.js` | 10 款装备的场景、配色、解锁和顺畅评分 |
| `content/stools.js`、`specimens.js` | Bristol 七型、56 款便便、稀有度与固定分类 |
| `content/stool-properties.js` | 硬度、凝聚、延展、颗粒、蓬松五项 1～7 属性 |
| `content/stool-recipes.js` | 46 款普通便便的食物集合＋饮料＋力度固定配方 |
| `content/stool-forms.js`、`specimen-blueprints.js` | 固定结构与每款唯一图鉴条目 |
| `content/colors.js`、`marks.js`、`force.js` | 色素、食材印记、力度区间与指针 |
| `game/selection.js` | 默认值、有效 ID、食物去重及添加剂单选限制 |
| `game/food-profile.js` | 按影响强度合并食品属性，主食权重乘 2，独立保留食材身份 |
| `game/outcome-pool.js` | 唯一的最终概率池、固定配方匹配、形态属性、预告与普通兜底 |
| `game/drops.js` | 从最终池抽完整品种，再生成个体外观种子和评分 |
| `game/stool-type.js` | 从同一最终池汇总七型概率，不另算一套形态分布 |
| `game/effects.js`、`smoothness.js` | 收集外观、装饰、食材印记和顺畅评分，不累计产出倍率 |
| `game/color.js`、`food-appearance.js`、`explanation.js` | 本次颜色、残留、纹理、装饰和结果诊断 |
| `game/specimen.js`、`session.js` | 按成品结构归类，单局冻结、恢复与结算 |
| `progression/` | 食物解锁、独立个体、收藏与马桶拥有/装备 |
| `storage/` | 当前模型校验、本地读写与多标签页结算锁 |
| `ui/` | 手机场景、选择浮窗、结果、图鉴、稀有演出与音效 |

依赖方向为：内容/配置 → 游戏规则 → 养成/存档 → 界面。游戏只用根目录 `styles.css` 一套手机布局；Admin 是独立工具。界面规范见 [手机界面规范](手机界面规范.md)。

## 一局输入

```js
{
  foodIds: ["rice", "enoki"],
  drinkId: "water",
  water: 1500,
  additives: ["probiotic"], // [] 或一个有效添加剂 ID
  toiletId: "standard",
  digestionTime: "4",       // 2 / 4 / 8 / random，过程记录
  force: 50                 // 0～100，停止时确定
}
```

食物 1～3 种、饮料 1 种、添加剂 0～1 种、马桶 1 款。`normalizeSelection` 负责统一输入；开局另行检查食品解锁与马桶拥有。马桶 3 款初始解锁，其余按完成次数解锁；消化和马桶不参与产出概率。

## 从输入到结果

1. 开始时规范选择，创建单局 ID 并启动力度指针；此时没有便便结果。随机消化只记录一个过程档位。
2. 停止时锁定力度，`outcome-pool.js` 匹配食物集合、饮料和力度，不把添加剂当作配方条件。
3. 最终池先保留全部 10 款稀有的基础总 2%；对应功能剂合计再加 3 个百分点，变为 5%。没有来源门槛。
4. 若配方匹配，普通预算的 80% 给目标；选择益生菌则给 100%。默认总体目标分别为 78.4% 和 98%；稀有功能剂下普通目标总体为 76%。
5. 剩余普通预算按五项属性、食品集合和饮料的接近程度取最近 3 款，再按 `1 / (1 + 距离)` 分配。已分配固定预算的目标不参加兜底。
6. `drops.js` 第一次随机直接选择完整条目；第二次随机只生成 `variationSeed`，用于该个体的外观变化。
7. 装配颜色、印记和装饰，按固定结构归入 Bristol 分类，计算顺畅度与分数；停止时冻结完整结果。
8. 约 400 ms 后结算，追加一个独立个体。刷新不重抽锁定结果，同款新个体不覆盖历史。

游戏预告、Admin 预览、七型分布均从同一最终池读取。完整公式及字段方向见 [便便产出算法说明](便便产出算法说明.md)。

## 内容维护入口

所有内容使用稳定唯一 ID，便便品种与分类一一固定，颜色和残留不增建品种。

普通配方数据只含四个字段：

```js
{
  characterId: "classic",
  foodIds: ["rice"],
  drinkId: "water",
  forceZone: "medium"
}
```

食品集合无序且必须完全相同；每款普通便便恰有一条配方，相同输入只允许对应一个目标。改配方后同步维护 [固定配方表](固定配方表.md)，核对所有食品与饮料 ID 有效。

`stool-properties.js` 提供五项形态属性，`specimens.js` 的 `properties` 保存每款属性。稀有款有自身固定形态，不在普通品种上临时套稀有材质。

添加剂单选，其功能使用明确字段：

| 字段 | 用途 |
| --- | --- |
| `stability` | 普通兜底时增加硬度接近的重要性；益生菌还将匹配配方稳定为普通分支 100% |
| `propertyChanges` | 自由组合和普通落空分支的硬度、凝聚、颗粒等修正 |
| `decoration` | 直接叠在实际产出上的闪粉、金箔、花瓣等 |
| `rareTargets` | 稀有功能剂的目标 ID，共享明确的＋3 个百分点加成 |
| `effects.smoothnessBonus` | 顺畅评分，不参与产出概率 |

食品原有九项属性和值保留，主要由后台编辑。饮料使用 `hardness` 和 `porosity`，其他形态以食品为主。马桶只保留外观、解锁和顺畅评分。标签可以用于内容描述和颜色，不再作为稀有入场资格。

修改内容后运行内容文档生成器；便便仍为 56 款、每款一个固定分类、普通配方 46 条、素材与 ID 完整。游戏和 Admin 均不提供搜索，使用分类、分页和详情切换。

## 图鉴、美术与稀有呈现

图鉴为「全部＋七型」，未发现款默认统一剪影。右上角「全部样式」可查看实际造型和大图，不写收藏；详情可切换「形态」与「配方」。普通配方展示基础条件 80%、益生菌 100% 及整局概率，稀有详情说明每轮机会和功能剂。

美术入口为 `ui/artwork/stools.js`。19 款参考图透明 PNG 由 `content/stool-art-assets.js` 映射至 `assets/stools/reference-v2/`；其余 37 款使用统一光照的原生预渲染 PNG。旧六格 WebP 图集已退出运行时引用；食材印记、颗粒、气孔、颜色和装饰由外观层装配。美术管线与素材边界见 [便便美术制作说明](便便美术制作说明.md)。

稀有演出读取已经冻结的结果，使用标题、配色、材质纹样、粒子和短音效；不重新抽取、不更改奖励，也不延迟操作。减少动态模式保留静态效果。

## 存档、后台与发布

本地存储键为 `lalala-dev`，存档版本 5。每次产出保存独立 ID、品种、结构、分类、外观与配方；单局 ID、结算记录和 Web Locks 防止重复结算。当前模型校验不会把缺少结构的旧记录补造成新个体。

`admin/` 是开发工具，支持食品分类、九项属性与色素编辑、草稿比较和批量保存。配方试验可选饮料、水量、单一添加剂、模拟力度、消化档位与马桶，直接显示实际目标及稀有概率。固定目标的 80% / 100% 不受食品调参改写。

`GET/PUT /api/admin/foods` 只管理 `food-attribute-values.js`，校验 ID、同源、版本冲突并原子写入。`scripts/build.mjs` 按运行时白名单生成 `dist/`，排除后台、接口、开发脚本、测试与文档。发布预览禁用管理页面与写入接口。

验证按本轮改动范围执行，重点核对配方唯一性、目标及稀有精确概率、单选限制、装饰可见、时间/马桶概率独立以及结果冻结。历史测试数量不作为新规则的验收结论。后台使用见 [食物调参指南](食物调参指南.md)，完整模块入口见 [配方实验室指南](配方实验室指南.md)。
