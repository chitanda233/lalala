# 手机单屏交互规范

以手机为唯一主设计目标，屏幕比例参考 [iPhone 18 Pro 官方显示屏规格](https://www.apple.com.cn/iphone-18-pro/specs/#display)的 1206 × 2622。网页实际铺满手机可用宽高，浏览器工具栏、安全区和键盘都会改变可用空间；不把自行换算的逻辑尺寸说成设备官方规格。

## 页面与样式

- 游戏只保留 `styles.css` 一个样式源，无桌面版/手机版布局分支。大屏居中展示同一手机界面。独立开发 Admin 继续使用自己的工具样式。
- 页面高度来自实际 visualViewport，支持动态浏览器栏。页面与浮窗都不允许上下滚动。
- 中央是马桶，下面依次为状态、预留的力度指针位置、固定开始/停止按钮；配方摘要在下方。
- 左侧为食物、饮料、添加剂，右侧为消化时间，右上角为图鉴。点击中央马桶更换装备，底部是玩法与音效。
- 力度指针只在开始后出现，使用预留区域，不改变按钮坐标。锁定后 400 ms 揭晓。

## 阅读与密度

- 手机主要正文和操作名称至少 14 px，主入口与卡片名称 16 px，主按钮 20 px，辅助标签至少 12 px。标题使用 21～30 px。
- 使用深绿文字增强对比度，去掉装饰性英文小标题，收紧空白。主插图、卡片和触控入口一起放大。
- 卡片数量跟随当前实际高度，浏览器工具栏变化时重新分页；保持双列，优先可读字号，不用缩字换取更多格子。

## 浮窗

主界面选定配方后、力度摆动时及锁定等待时均不展示预测结果、分型、命中率或稀有概率，也不指示目标造型的理想力度；保留配方输入、通用操作提示和当前力度，结果在揭晓时出现。概率与配方说明仍可在图鉴和后台主动查看。

- 食物库：分类、双列大卡片，按可用高度每页 2 / 4 / 6 种，已解锁在前；卡片右上角“＋”直接加入餐盘，已选显示“✓”，再次点击即移除，选满三种也可取消已选项；卡片主体用于查看介绍，描述区不再放“加入餐盘”按钮。打开时定位已选食物，简短介绍和属性、三个餐盘槽与确认始终可见。确认才提交，取消保留原餐盘。游戏与 Admin 均不提供搜索框或搜索匹配功能。
- 饮料、添加剂：整体沿用食物的卡片库、描述区、添加栏和确认／取消结构，卡片主体只切换介绍，“＋／✓”负责加入。各保留一个添加槽位，翻页时始终可见；点击槽位可定位已选卡片，叉号可移除，饮料为空时不能确认，添加剂可不加。饮用量保留在饮料浮窗中；饮料、饮用量和添加剂都在确认后保存，取消不改原配方。
- 消化时间：主界面入口完整显示“消化时间”；2（短时）、4（适中）、8（较久）及随机四档。说明明确这些是时间档位而非便便分型，短时偏湿、较久偏干，不增加实际等待。
- 图鉴：全部与七型筛选，双列大卡片，按可用高度每页 2 / 4 / 6 种。未知收藏统一虚影；点击已发现条目进入独立详情视图，可返回原图鉴页。个体按品种去重后保留最近7个，同款只展示最新个体，不合并印记；旧个体清理后仍展示已解锁样式、配方和来源，不显示失效的个体切换箭头。
- 结果：保留独立个体、分类、诊断与稀有专属演出，主视图突出大图、名称和诊断；配方与力度等记录放入可展开的诊断详情，所有动作在一屏内可达。

后续修改必须验证首页、所有浮窗、力度阶段和普通/稀有结果的完整路径；检查可见内容的尺寸，不能以 overflow:hidden 掩盖内容溢出。
