# 需求规格说明

版本：整理版 1.2。整理日期：2026-10-17。适用阶段：开发与正式内容筹备。

本文件从用户的连续对话整理要求，后发要求覆盖早先方案。具体名单、参数初值、概率阈值、模板数量等实现补充见 [自主补充的设计与实现](implementation-decisions.md)，不混作用户逐项指定的规则。

## 1. 产品方向与模块

以食物配方影响便便的形态、外观与特殊产出，形成可反复尝试和收集的游戏。便便应是干净、有趣、值得收藏的风格化藏品。

模块按食物、饮料、添加剂、马桶、产出规则、便便个体/图鉴和开发 Admin 分开，便于以后维护正式内容。内容数据、计算规则和界面职责应可区分。

| 编号 | 用户要求                         | 验收标准                                                             |
| ---- | -------------------------------- | -------------------------------------------------------------------- |
| R-01 | 以最新需求为准                   | 日常开发直接维护当前模型，不并行保留新旧玩法和两版界面               |
| R-02 | 配方共同决定便便，并在便便上体现 | 多种食材共同参与形态与外观；结果可见对应印记、色泽或纹理             |
| R-03 | 每次便便都是独立个体             | 同款重复产出分别保存，不能覆盖上次，也不能把多次印记合成一只         |
| R-04 | 按健康形态分类学归类             | 当前采用 Bristol 1～7 型；具体条目有固定结构，个体分类与可见形态相符 |

当前为固定结构模板候选与外观叠层的实现，不把“任意连续几何生成”视为已经完成。用户要求的是产出关系和独立个体，具体模板模型由实现选择。

## 2. 食物

| 编号 | 用户要求                                         | 验收标准                                                                     |
| ---- | ------------------------------------------------ | ---------------------------------------------------------------------------- |
| R-05 | 同时包含网络梗、常见食物及容易影响形态的内容     | 包含华莱士汉堡、金针菇、香蕉、观音土；可扩充成品、原材料、地区食物与幻想内容 |
| R-06 | 一餐最多三种食物                                 | 选择浮窗下方有三个格子，可添加本餐食物                                       |
| R-07 | 上方展示已解锁和未解锁食物                       | 已解锁排前，未解锁排后；未解锁不能加入本餐                                   |
| R-08 | 食物可查看简单描述                               | 选中后可看介绍，可幽默或正式，不要求冗长营养说明                             |
| R-09 | 食材有可调属性，控制便便形态和可见食材特征       | 属性方向清楚，能看实际影响，参数进入真实规则而非只做展示                     |
| R-10 | 最新软硬程度方向为 1 很软、7 很硬                | 所有编辑标签、实际计算和说明一致；不能沿用早期相反方向                       |
| R-11 | 影响强度应在最外层                               | 独立显示，不与食物颜色一起折叠；色素和高级属性职责分开                       |
| R-12 | 香蕉容易偏软，金针菇吃后一定体现，华莱士容易拉稀 | 香蕉偏软、华莱士偏松散/水样但保留随机；金针菇特征跨不同造型与稀有材质保留    |
| R-13 | 去掉“趣味食物”分类；关闭整个搜索功能             | 当前游戏和 Admin 都没有搜索框或搜索匹配逻辑；通过分类、分页浏览              |

用户已接受食物属性方案。当前采用九项 1～7 数值：软硬程度、凝聚度、延展性、颗粒感、形态保留度、染色能力、蓬松度、顺滑度、影响强度，另选色素。具体字段键和数值表见 [食物文档](foods.md)。食物名称与现实身体反应的联系属于游戏创作，不是现实医学规则。

初次要求找 30 种，之后要求香蕉、观音土和另外 20 种。香蕉已在原有清单中；当前 51 种是实现结果，不是用户逐项批准过的正式最终总量。

## 3. 饮料、添加剂与马桶

| 编号 | 用户要求                       | 验收标准                                               |
| ---- | ------------------------------ | ------------------------------------------------------ |
| R-14 | 食物、饮料、添加剂是不同子模块 | 数据和入口分开，能共同参与一份配方                     |
| R-15 | 马桶有不同种类                 | 点击中央马桶打开预览，箭头翻页，点击“蹲它”装备；未解锁按钮上方直接展示解锁条件和进度                                 |
| R-16 | 马桶影响顺畅度和特殊产出概率   | 换装备会改变相应数值或符合资格候选的权重，而非只换皮肤 |

饮料选一种、添加剂最多三种、20/18/10 的数量、三款初始开放的具体名单、解锁次数及具体装备能力均为实现补充，不是用户单独规定的正式数值。完整内容见 [饮料](drinks.md)、[添加剂](additives.md)、[马桶](toilets.md)。

## 4. 消化时间与力度

| 编号 | 用户要求                                           | 验收标准                                                          |
| ---- | -------------------------------------------------- | ----------------------------------------------------------------- |
| R-17 | 右侧“时间”表示消化时间                             | 提供 2、4、8、随机，参与产出形态；不能误作揭晓倒计时              |
| R-18 | 参考肠道停留时间与形态关联                         | 保留研究出处；游戏数值映射与现实证据分开说明                      |
| R-19 | 开始拉屎后才启动往复指针                           | 空闲时不摆动；左侧力度低，右侧力度高，持续往返                    |
| R-20 | 玩家再次点击停止，按锁定的力度区间取代出场方式选择 | 不再提供旧“拉屎出场方式/节奏”下拉选项，实际力度影响规则           |
| R-21 | 锁定后快出结果，按钮别跳动                         | 提示和指针显隐不改变开始/停止按钮的位置；当前实现为约 400 ms 揭晓 |

往复 3 秒周期、0～100、三段力度阈值、消化档位的 +1/0/−1 偏移及随机等概率为实现选择。2/4/8 当前是压缩游戏档位，没有标成现实小时；正式时间单位仍可另行确定。研究与公式见 [算法说明报告](food-outcome-algorithm.md)。

## 5. 便便、图鉴与描述

| 编号 | 用户要求                                       | 验收标准                                                                   |
| ---- | ---------------------------------------------- | -------------------------------------------------------------------------- |
| R-22 | 图鉴直接按分类学分类，再加“全部”               | 入口为全部和七型，不再用食物来源作为主分类                                 |
| R-23 | 未解锁/未发现便便统一虚影                      | 不直接露出真实图片，不靠真实轮廓或材质提前透露具体藏品                     |
| R-24 | 黄金、晶体、彩虹、果冻都是稀有款，不能轻易产出 | 配方只影响机会，稀有仍需抽取；当前共同上限为实现补充的 0.5%                |
| R-25 | 稀有产出有不同呈现                             | 稀有材质有相应结果演出，且不改变已经确定的结果                             |
| R-26 | 大便描述是对形态的诊断                         | 描述软硬、成形、轮廓、纹理、颜色和残留，玩家结果中不展开冗长来源与权重日志 |
| R-27 | 完美连续螺旋需要合理分类                       | 当前按柔软连续成形归入 4 型；螺旋作为造型而非另设一类                      |

便便品种总数固定为 **50 种**。每种只有一个图鉴条目和一个固定健康形态分类，不允许按七型展开出额外品种。颜色、食材印记和同款多次产出的独立个体都不增加品种数。见 [便便文档](stools.md)。

## 6. 统一美术

用户上传《便便收藏游戏_统一美术风格提示词.md》，并要求便便形态符合这份参考。项目内保留于 [art-direction.md](art-direction.md)。

采用的视觉要求：风格化 3D、软陶玩具/幻想藏品质感、圆润清爽、统一轻俯视展示与柔和灯光；不强行所有便便都用尖顶螺旋；七型轮廓有区别；默认无五官、无写实污物和生理细节。食材印记也以干净、设计化的方式表现。

资料中的五档品质、可旋转查看、具体生成器建议和示例品种是参考内容，并不自动成为全部必须实现的功能。当前是三档数值稀有度和静态素材叠层，差异在 [实现记录](implementation-decisions.md) 明确说明。

## 7. 手机单屏交互

| 编号 | 用户要求                       | 验收标准                                                                                   |
| ---- | ------------------------------ | ------------------------------------------------------------------------------------------ |
| R-28 | 后续以手机为准，不维护两套 CSS | 游戏只用 styles.css 一个布局源；大屏展示同一竖屏界面                                       |
| R-29 | 参考 iPhone 18 Pro 的竖屏比例  | 按实际可用视口、安全区和浏览器栏铺满，不能锁死为自行换算的小画布；402×874 只能作为测试尺寸 |
| R-30 | 一屏内完成操作，不能上下滚动   | 首页、选择浮窗、图鉴、结果和详情可完整操作；大清单分页，不用裁切掩盖溢出                   |
| R-31 | 固定布局位置                   | 马桶在中央，开始按钮在下方；左边食物、饮料、添加剂；右边消化时间；右上角图鉴               |

当前双列大卡片、按可用高度每页 2 / 4 / 6 格、奶油色与薄荷绿配色、马桶名称作为装备入口、底部餐盘摘要及玩法/音效入口是实现补充。Admin 为独立开发工具，有自己的工具样式，不构成游戏的另一套端侧布局。

## 8. 开发 Admin 与算法文档

| 编号 | 用户要求                                           | 验收标准                                           |
| ---- | -------------------------------------------------- | -------------------------------------------------- |
| R-32 | 作为策划自己的管理页，日常一起开发，正式发布不打包 | 本地可用，发布产物与预览不能访问后台页面和管理接口 |
| R-33 | 参数容易调控，能理解食物到产出的对照算法           | 说明字段、实际规则与预览含义，保存值进入真实游戏   |
| R-34 | 算法写报告放项目 docs 目录                         | 保留可读说明、公式、来源与可运行核对方法           |

当前 Admin 只管理食物属性，饮料、添加剂和马桶在配方预览里可选；它们自身、便便条目与产出规则尚需编辑源码。保存冲突检测、草稿比较、撤销当前食物、重新载入等属于工程补充。

## 9. 当前验收方式与待定事项

按“选食物 → 配饮料与添加剂 → 时间/装备 → 开始 → 往复指针 → 停止 → 快速结果 → 图鉴个体 → 刷新恢复”的完整路径验收，覆盖解锁、未发现隐藏和稀有表现；检查单屏完整性与按钮位置。

当前已完成这些主要链路，最近一轮自动验证为 71 项单元与 64 项浏览器测试通过。仍需注意：这不是手机真机测试结论；金针菇被管理员调成保留度 1 的行为与用户“必定体现”要求存在边界；正式内容的解锁、数值平衡、个体外观差异强度与时间单位尚未定稿。完整列表见 [实现差距与后续决定](implementation-decisions.md#需要明确的边界与后续决定)。

## 10. 阅读舒适度补充（最新要求）

用户明确反馈整体 UI 与字体太小、留白太多、阅读费力。所有主要游戏界面应提高字号和文字对比度，放大主要卡片和插图，收紧无效空白；继续遵守手机单屏操作及按钮固定。具体字号层级、双列卡片与按高度分页属于实现选择，见 [手机交互规范](mobile-ui.md)。
