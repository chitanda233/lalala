# 自主补充的设计与实现

整理日期：2026-10-17。规则版本 13，存档版本 5。

本文件回答“哪些是为了落实需求由我自行发挥的，以及具体怎样实现”。以下“补充”只说明设计归属，不表示要推翻现状，也不把所有补充当成用户逐项确认过的正式规则。当前配置可能包含之后由用户保存的调参；文档按实际值记录，不追溯每个数值的修改人。

## 配方到产出的具体算法

### 输入与默认值

| 项目     | 当前值                            | 源码                                        |
| -------- | --------------------------------- | ------------------------------------------- |
| 食物     | 1～3 种，不重复；默认白米饭       | [selection.js](../src/game/selection.js)    |
| 饮料     | 一种；默认清水                    | [selection.js](../src/game/selection.js)    |
| 添加剂   | 0～3 种，不重复                   | [game.js](../src/config/game.js)            |
| 饮用量   | 250～2500 mL，步长 250，默认 1500 | [game.js](../src/config/game.js)            |
| 消化时间 | 2/4/8/random，默认 4              | [digestion.js](../src/content/digestion.js) |
| 力度     | 玩家测定 0～100；预告默认 50      | [force.js](../src/content/force.js)         |
| 马桶     | 一款，默认经典白瓷                | [toilets.js](../src/content/toilets.js)     |

饮用量不会把咖啡或添加剂效果按毫升线性放大，没有热量、容量、配料克数的另一次计算。

### 属性合并

六项餐盘参数（软硬、凝聚、延展、颗粒、蓬松、顺滑）按影响强度加权：

```text
餐盘属性 = Σ(食物属性 × 食物 influence) / Σ influence
```

先去重并按 ID 排序，因此食物格子顺序不影响规则。influence 主要改变混吃占比，单吃只有一个来源，提高它不会把所有效果机械放大。

食物保留度逐项保存；食物色素按染色能力 × 影响强度选一个主色素，而非把三种颜色平均。食物 effects 只保留特定收藏倍率和稀有加成，旧的食物 typeShift 等不重复叠加；饮料、添加剂、马桶和力度继续使用通用 effects。

来源：[food-profile.js](../src/game/food-profile.js)、[effects.js](../src/game/effects.js)。

### 形态亲和度

基础方向为 8 − 餐盘硬度，先加入饮用量分段偏移：

| 饮用量        | 偏移     |
| ------------- | -------- |
| 250～500 mL   | −3，偏硬 |
| 750～1000 mL  | −2       |
| 1250 mL       | −1       |
| 1500～2000 mL | 0        |
| 2250～2500 mL | +1，偏软 |

偏硬且水量至少 1000 时，较高凝聚度可向 4 靠近；typeBalance 也向 4 拉近，然后加入消化和其他 typeShift，四舍五入并限制 1～7。总偏移限 −2～+3、平衡最多 2、稳定度最多 0.18。

中心结构初始权重比例为 min(0.95, 0.8 + 稳定度)，剩余分给相邻结构。凝聚/延展再按兼容程度调整并归一化；液态保留水样轮廓。它是构建完整候选的亲和度，不另抽一次分类。

来源：[recipe-shape.js](../src/game/recipe-shape.js)。所有系数是虚构策划值，研究仅支持快慢方向，不支持这些具体时间或系数。

### 品种候选、稀有与抽取

基础品种偏好按优先级选择：水量 ≤750 → pebble；辣味 → fire；咖啡 → coffee；益生菌且水量 ≥2000 → cloud；之后绿色 → garden；否则食物外观票数决定。偏好品种的固定分类必须匹配当前结构，否则采用已有的七型基础品种（pebble、stacked-stones、cracked、classic、soft-pillows、mashed-potato、pancake），不生成同种的其他类型版本。再加入符合条件的其他固定品种。

普通与特别点缀候选在各结构组内合计归一为 100 权重。特殊造型可受凝聚、延展、蓬松和顺滑的指数倍率影响。稀有候选先查资格，再叠加配方和设备倍率，合计按共同预算压缩；最后与结构亲和度组成完整条目池。

0.5% 是八种 special 的合计上限。×4 表示权重倍率，不能读作 4% 或保证掉落。黄金没有强制金箔来源，符合形态、水量和排斥条件即可低概率进入；其他七类要求各自来源标签。闪粉、碎金、银霜等 uncommon 属于普通预算，不代表整块稀有材质。

锁定时第一次随机选完整 specimenId，第二次随机给 variationSeed；之后按 morphology.form 读取 Bristol 分类。随机消化额外在开始时抽一次档位，预告用三档完整池的平均。

来源：[combinations.js](../src/game/combinations.js)、[outcome-pool.js](../src/game/outcome-pool.js)、[drops.js](../src/game/drops.js)。全部品种和条件见 [便便文档](stools.md)，长公式与核对例子见 [算法说明报告](food-outcome-algorithm.md)。

## 在便便上具体体现什么

| 参数/来源        | 当前可见实现                                                    | 边界                                             |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------ |
| 软硬、凝聚、延展 | 改变结构与造型候选概率；3/4 型轻微横向伸展                      | 有限形态模板，不是任意实时建模                   |
| 颗粒、蓬松       | 主体遮罩内的颗粒和气孔纹理                                      | 风格化装饰，不是写实组织                         |
| 食材保留         | 普通食材以自身小图案按保留度改变数量/大小/透明度                | 只保留 retention>1 的食材                        |
| 金针菇           | 每个实际条目对应的专属 3D 印记叠层                              | 当前 retention=7；调成 1 会关闭                  |
| 色素             | 材质/固定色优先，其后饮料、添加剂、食物；普通主体按染色强度混色 | 稀有材质不被普通色素盖掉；不做三食物色彩物理混合 |
| 设备和配方标签   | 木纹、暖卷、珠串、石塔、喷射、螺旋等对应候选                    | 标签提供资格，仍有其他结果                       |
| 个体种子         | 纹理相位、残留位置与约 ±1.5° 朝向                               | 同款个体不保证轮廓完全不同                       |

普通残留数量为 1 + floor((保留度−2)/2)，尺寸为 10 + 保留度×2.2，不透明度为 0.25 + 保留度×0.085；不是按概率抽“是否消化”。普通主体染色比例为 (染色能力−1)/6。来源：[artwork/stools.js](../src/ui/artwork/stools.js)。

当前是开发期统一渲染后导出静态透明 PNG，运行时用 SVG 包装与叠层；164 张素材包含 50 组主体/装饰/金针菇印记及七型兜底。用户参考中的可旋转 3D 查看、五档品质并未直接实现。来源：[美术实现](stool-art.md)。

## 力度、时间、顺畅和得分

指针为 3 秒往复：1.5 秒从 0 到 100，再用 1.5 秒回到 0。玩家可以等待多个周期，没有自动结束。

| 力度           | 当前补充效果                                          |
| -------------- | ----------------------------------------------------- |
| 0～33 轻力度   | 顺畅 +0.5、稳定度 +0.08；提供 low-force；螺旋要求该档 |
| 34～66 中等    | 无额外偏移                                            |
| 67～100 强力度 | 偏软 +0.6；提供 high-force；喷射要求该档              |

2/4/8 消化档位分别加 +1/0/−1 结构偏移；随机从三档等概率选择，选定后刷新不重抽。消化不造成额外真实等待。锁定后 400 ms 揭晓。

顺畅基础值按 1～7 型为 [1,2,4,5,3,2,1]，加上 (餐盘顺滑−4)×0.5 和其他来源加值，取整并限 1～5。分数为 round(min(100,50+顺畅×9+黄金额外5))。分数和顺畅五格是我添加的反馈，当前没有兑换或消耗用途。来源：[smoothness.js](../src/game/smoothness.js)、[drops.js](../src/game/drops.js)。

## 单局、个体和开发后台

开始时保存配方、UUID、摆动起点和实际消化档位，处于 aiming，没有结果；停止时按同一时刻测力度，生成并冻结完整结果，进入 running；400 ms 后结算并追加一个独立个体。多次点击、刷新或多标签页不会重复发放，同款新个体不覆盖历史个体。存档键为 lalala-dev，当前规则版本 13、存档版本 5。

结果冻结的是**停止时生成的结果**。开始到停止期间不保存完整食物参数副本；若通过开发工具在摆动期间更改源码并刷新，当前规则可能参与尚未发生的抽取，不能笼统承诺“点击开始就冻结所有参数版本”。

Admin 只编辑九项食物数值和色素，可预览加入另两种食物、饮料、饮用量、添加剂、力度、消化时间和设备的效果。已保存/草稿对照使用实际规则，代表图是概率最高普通条目的稳定示例，不是一次历史产出。磁盘保存校验版本、序列化写入并原子替换，避免覆盖其他编辑。正式 dist 排除 admin、管理接口和开发脚本。

来源：[session.js](../src/game/session.js)、[individuals.js](../src/progression/individuals.js)、[Admin 指南](food-admin.md)、[build.mjs](../scripts/build.mjs)。
